## What Was Built

### Components

- Transactional SQLite reference store with exclusive notification claims and decision compare-and-set.
- Stable notification idempotency keys and duplicate request reuse.
- Teams Adaptive Card rendering with server-authoritative decision payloads.
- Proactive Teams HTTP adapter with typed retry behavior.
- Microsoft Graph Outlook fallback adapter.
- Deny-by-default actor-group authorization.
- Idempotent approval, rejection, expiry and replay handling.
- MLflow alias promotion with stale-precondition protection.
- Four Airflow DAGs: collect, dispatch, apply and reconcile.
- Automatic mapped delivery task after successful self-healing PR creation.
- Contracts for notifications, decisions and applications.
- Teams app manifest template and infrastructure gate checklist.

### Safety Properties

- Delivery failure cannot recreate a branch or PR because notification runs in a downstream task.
- A duplicate source result reuses the existing notification and decision.
- Card payload cannot replace the authoritative resource or model version.
- Rejected or expired decisions cannot create an application.
- PR approval/merge remains in GitHub; delivery code contains no merge operation.
- Model alias changes are blocked when registry state differs from the reviewed state.

## Deviations and Lessons

1. SQLite replaced Delta for the local decision ledger because approval and dispatch claims require transactional compare-and-set. This directly addresses the checkpoint race found during remediation.
2. Interactive cards require a Teams app/bot and `adaptiveCard/action`; Microsoft Graph alone is not the callback mechanism.
3. Full-stack Airflow validation remained resource-heavy, but isolated disposable containers produced a deterministic DagBag gate in about one minute.
4. Delivery must be downstream of PR creation. Coupling both effects in one retryable task would duplicate branches/PRs.
