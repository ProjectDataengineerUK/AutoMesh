## Lessons Learned

### Process

- Separate unit, DagBag, security and report workflows from the start; combining dependency-heavy gates makes failures slower and less attributable.
- Treat the first GitHub Actions run as part of Build verification, not post-Ship administration. It exposed two dependency-boundary defects that local tests could not reproduce.

### Technical

- A top-level package named `platform` shadows Python's standard module. If the approved path must remain, compatibility with the standard API needs an explicit test on every supported Python version.
- Domain-isolated CI requires each domain to declare transitive runtime imports. FinOps reused self-healing persistence but initially omitted `pyarrow` and `deltalake`.
- Skipped and expired evidence must remain first-class states; treating absence as success would overstate operational maturity.

### Communication

- Reporting “implemented” separately from “infrastructure validated” prevented local mocks and passing CI from being misrepresented as Microsoft 365 or Databricks proof.
- Calling out the managed Windows temporary-directory limitation early kept local failures distinct from Linux CI regressions.

### Tools & Libraries

- GitHub Actions domain matrices and isolated Airflow containers produced clear, independently actionable gates.
- PyYAML, immutable dataclasses and JSON artifacts were sufficient for an auditable validation plane without adding an operational database.

## Recommendations for Future Work

| Area | Recommendation |
|---|---|
| Package layout | Rename the internal `platform` package in a compatibility release to eliminate standard-library shadowing |
| External validation | Provision one allowlisted test environment per capability and run read-only smokes with expiring evidence |
| Coverage | Add coverage publication and thresholds after establishing a stable domain baseline |
| Dependency management | Generate or validate per-domain lock files and test import closure in CI |
| Branch protection | Require quality, DagBag, security and validation-report checks on `main` |
| Telemetry | Add an authorized external exporter only after retention, cost and access policies are approved |
